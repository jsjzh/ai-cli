## AI 对话

### 问题一

刚才我说希望 frontend-slides 只对于 ai-ppt 的目录生效，有个问题，为什么不能像 plugin 一样，写在 opencode.json 中，实际的内容放在 cache 里，就好比：

{
"$schema": "https://opencode.ai/config.json",
"plugin": ["@dietrichgebert/ponytail"],
"instructions": ["AGENTS.md"]
}

### 回复一

你说得对，这确实是个设计不一致的地方。

目前 opencode 的机制是这样的：

| 类别                   | 声明方式                      | 存储位置                            |
| ---------------------- | ----------------------------- | ----------------------------------- |
| **Plugin**             | `opencode.json` 里写 npm 包名 | npm cache / node_modules            |
| **Instructions/Rules** | `opencode.json` 里写路径      | 项目内任意位置                      |
| **Skill**              | ❌ 不支持声明式引用           | 必须物理放在 `.opencode/skills/` 下 |

Skills 目前**只能通过文件系统发现**，没法像 plugin 那样写个 npm 包名或 URL 就让 opencode 去下载/引用。这意味着：

- 全局 skill 只能放 `~/.config/opencode/skills/` → 所有项目都能看到
- 项目 skill 只能放 `.opencode/skills/` → 只有该项目能看到
- 没法实现"声明引用，实际内容放缓存"的模式

如果要实现你想要的效果（类似 plugin 的声明式引用），这是 opencode 本身需要加的功能——例如支持：

```json
{
  "skill": ["frontend-slides"]
}
```

然后从 npm 或官方 registry 拉取。但目前这个功能还不存在。

不过你的需求（**让 skill 只对特定项目生效**）刚才的移目录方案已经满足了。你是在问为什么设计成这样，还是想换个方式来实现？

### 问题二

我想把这个 skill 存在一个公共的地方，然后通过声明的方式来引用，如果想做到这个你有什么方案

### 回复二

从现有能力出发，最实用的方案是 **软链接**：

方案：共享存储 + 项目级软链接

**公共存放点：**

```
~/.local/share/opencode-skills/frontend-slides/   ← skill 只放这里一份
```

**项目引用（声明方式）：**

```bash
ln -s ~/.local/share/opencode-skills/frontend-slides 项目/.opencode/skills/frontend-slides
```

每个要用的项目只需执行这一句，效果上就相当于"声明式引用"了。`ls -l` 看到的是：

```
.opencode/skills/frontend-slides -> ~/.local/share/opencode-skills/frontend-slides
```

**优点：**

- Skill 只存一份，不重复
- 只有声明了的项目才生效
- 可以在 `.gitignore` 里加 `.opencode/skills/` 避免提交
- 更新公共目录，所有项目自动生效

**缺点：**

- 每个项目需要手动执行一次 `ln -s`
- 可以写个脚本一键管理，比如 `skill-link add frontend-slides`

---

也有其他思路但各有取舍：

| 方案                           | 问题                                           |
| ------------------------------ | ---------------------------------------------- |
| `instructions` 引用 skill 文件 | 始终加载到上下文，失去按需加载能力，浪费 token |
| 用 `OPENCODE_CONFIG_DIR`       | 要通过环境变量设，每项目要改启动脚本，不够干净 |
| **软链接（推荐）**             | 最简洁，接近声明式                             |

你觉得软链接的方案可以接受吗？如果可以，我先在本地创建 `~/.local/share/opencode-skills/` 并把你之前移过去的 `frontend-slides` 移到那里，再给 `ai-ppt` 重新建软链接。
